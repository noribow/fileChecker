# 決定すべき要件 タスクリスト

`docs/requirements.md` の「9. 未決事項」を、依存関係を考慮して着手すべき順に整理したもの。

## 1. コア処理の基本方針（最優先・他の決定のブロッカー）

- [x] **1.1 ハッシュアルゴリズムの選定** — 決定済み（`docs/requirements.md` 10.1参照）
  - 外部お手本セット読み込み用にCRC32・MD5・SHA-1・SHA-256の4種を実装。自前形式の生成・重複チェック最終確定にはSHA-256を標準採用。
- [x] **1.2 重複判定アルゴリズムの方式** — 決定済み（`docs/requirements.md` 10.2参照）
  - サイズ一致 → CRC32(全体) → SHA-256(全体)確定の2段階方式。部分ハッシュ（ファイル先頭等）は不採用。

## 2. データ永続化設計

- [x] **2.2 リムーバブルメディアの識別方法** — 基本方針は決定済み（`docs/requirements.md` 10.4参照）
  - OSごとに切り替え可能な識別ロジック（プラットフォーム抽象化）とし、スキーマ上は `identifier_type` + `identifier_value` + `platform` の抽象形式で保持する。OS別の具体的な取得優先順は各OS実装時に定める。

## 6. 圧縮ファイル対応

- [x] **6.0 対応する圧縮ファイル形式** — 決定済み（`docs/requirements.md` 10.5参照）
  - zip・7zを対象とし、それぞれzstd圧縮方式にも対応する。読み取り（展開・ハッシュ照合）が必須機能、書き出し（再構成）は別機能として扱う。
  - 将来の対応形式拡張を見込み、DBスキーマ（`scanned_file.archive_format`）はCHECK制約等で形式を固定しない自由文字列とし、形式の妥当性判定はアプリケーション層で行う。
- [x] **6.1 圧縮ファイル展開時の安全対策** — 決定済み（`docs/requirements.md` 10.6参照）
  - 再帰展開は最大3階層。エントリ展開時はアーカイブ記載の宣言サイズを超えないことを検査。展開後サイズ上限は現時点で2TB。いずれも将来変更可能な設定値として保持し、ハードコードしない。
- [x] **6.2 暗号化・パスワード保護された圧縮ファイルの扱い** — 決定済み（`docs/requirements.md` 10.7参照。2026-09-01改訂）
  - パスワード保護された圧縮ファイル・エントリの復号には対応しない。検出時は復号を試みずエラー扱いとしてスキップする。パスワードの登録・管理機能は持たない。
  - **廃止**: 当初検討していた「登録済みパスワードによる復号」機能、およびそれに付随する保存方式・登録UI（旧6.4）・保護方式（旧6.5）の検討は、この方針転換により不要となった。
- [ ] **6.3 お手本セットに合わせた再構成（圧縮ファイル書き出し）機能の詳細仕様**（トリガー、TorrentZip/Torrent7z準拠の生成ロジック等）
  - 前提: 4.1/4.2（CLI/GUIのどこから起動するか）とも関連するため、それらの検討と合わせて後回しでよい
